## 3. 附录 A — 06:14 生产事故根因与整改（v1 <BAKE_IMAGE_DIGEST>）

**根因**：`model_arch_config_convertor.py` 的 CLEAN0 补丁调用 fork 不存在的 API —— `super().__init__(hf_config, hf_text_config, revision)` 三参，fork 基类 `ModelArchConfigConvertorBase.__init__` 只收两参 → head worker 启动即 TypeError 崩溃 → TCPStore(26000) 永不监听 → monitor 快速失败 → systemd 重启循环。`patch -p1` fuzz-0 通过 ≠ 语义兼容（正式教训）。
**修复**：v2 去掉 `revision` 实参（见 work 副本 :518）；烘焙期增加**真实实例化门**（convertor 在两套真实 config 上实调），防 CLEAN0 类静默回归。四机已统一 6637e26f。

**镜像 digest 疑云解答**：node01 `Ring=<INDEX_DIGEST>(35.6GB)` vs node02 `Ring=<CONFIG_DIGEST>(22.5GB)` —— 同一内容。<INDEX_DIGEST> 是 **OCI index digest**（构建机上 push 的多架构清单），<CONFIG_DIGEST> 是 **arm64 platform config digest**（pull 主机显示单平台）。registry 权威链已核：`/v2/.../manifests` 带 Accept 头取回 index → 解出 arm64 manifest → config digest 与四机本地一致。**四机本地镜像内容一致，无真不一致。**

**隐患记录（未修，移交 ops）**：
1. **stale cache**：start 脚本不做 `docker pull`，tag 重推后本地旧镜像会被继续使用 —— 任何 tag 复用前必须四机预拉（本次 -VL v2 已按此纪律预拉）。
2. **window_restart TCPStore 缺陷**：`[TCPStore up] 6x5s` 超时后**照样启动 workers**（06:14 链：start head 06:14:02 → 06:16:02 起了三台 worker）。应 fail-fast，否则 head crash 循环时白白拖三机进半初始化态。
