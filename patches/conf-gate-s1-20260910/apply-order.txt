# ----------------------------------------------------------------------------
#  5. 等价性论证：序 A ≡ 序 B（核心问题作答）
# ----------------------------------------------------------------------------
#  命题：base → dspark → dspark_speculator → scheduler_verify → w1_glue → w5
#        （序 A）与 base → scheduler_verify → w5（序 B，仅取 scheduler 链）
#        在 vllm/v1/core/sched/scheduler.py 上产出逐字节相同的文件。
#
#  理由（三步）：
#   1) 文件不相交：五条补丁中，只有 scheduler_verify.patch 与 w5_diag.patch
#      触及 scheduler.py；dspark / dspark_speculator 触及 dspark.py 与
#      speculator.py；w1_glue 触及 outputs.py / model_runner.py / engine_core.py。
#      → 对 scheduler.py 而言，序 A 中步 1、2、4 是 no-op，文件内容不变。
#   2) 相对顺序一致：两序中 scheduler_verify 都在 w5 之前 apply，且二者之间
#      无其它补丁改动 scheduler.py → w5 见到的上下文（行号基准）在两序中相同。
#   3) 实测印证：EXP3（序 A）与 EXP1（序 B）终态 cmp 逐字节相同，
#      且均等于 work/scheduler_diag.py。
#
#  ⚠️ 但"行号漂移"担忧不成立的原因正是 (1)——patch 的行号基准是【每个文件
#     各自的当前内容】，而非全局步数。其它文件被改动不会影响 scheduler.py
#     下一次 patch 的行号计算。故两序等价具有必然性，非巧合。
#
#  ⚠️ 唯一的【顺序敏感点】：w5 必须在 scheduler_verify 之后（依赖其引入的
#     _conf_gate / _conf_lengths / _conf_lengths_frame 符号）。破坏该顺序
#     → EXP2 所示 3/6 hunks FAILED。除此之外五补丁两两无顺序依赖。
